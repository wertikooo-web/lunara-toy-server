# Lunara / Lumi Toy Server: текущее состояние проекта

Дата среза: 2026-06-17  
Репозиторий: `wertikooo-web/lunara-toy-server`  
Продакшн URL Railway: `https://lunara-toy-server-production.up.railway.app/`

## Цель проекта

Lumi - голосовая AI-игрушка для ребенка 3-8 лет. Сервер принимает голос/текст из демо или устройства, распознает речь, отвечает через LLM, синтезирует голос и постепенно накапливает память ребенка и контентную базу.

Основная продуктовая цель сейчас: получить рабочий MVP, который можно тестировать с телефона, с памятью, коротким кэшированным контентом, базой контента и понятной логикой поведения.

## Текущая архитектура

Основной сервер: `server.js`.

Ключевые модули:
- `modules/llm.js` - системный prompt Lumi, история диалога, вызов OpenAI.
- `modules/tts.js` - маршрутизация TTS по языку, Yandex для русского, fallback/другие языки по текущей реализации.
- `modules/stt.js` - распознавание речи.
- `modules/memory.js` - PostgreSQL-память ребенка.
- `modules/content.js` - база контента, короткий кэш, ответы на загадки, локализация, аудио-кэш.
- `modules/storyEngine.js` - короткие сказки/истории на основе контентной базы.
- `modules/cleaner.js` - очистка временных аудиофайлов.

Основные данные:
- `data/content_seed.json` - сгенерированная база контента из Word-документов.
- `public/index.html` - телефонная/браузерная демо-страница.
- `public/manifest.webmanifest` и `public/icons/*` - PWA-иконка для ярлыка на телефоне.

## Память ребенка

Реализована PostgreSQL-память v1.

Идентификация:
- сейчас используется `device_id`;
- для демо можно использовать `DEFAULT_DEVICE_ID`;
- когда будет железо, device_id должен приходить от устройства.

Память хранится в `child_profiles`.

Старые простые поля сохранены:
- `child_name`
- `age`
- `favorite_color`
- `favorite_animal`
- `favorite_game`
- `favorite_toy`

Добавлена живая память в `memory_json`:
- списки предпочтений;
- любимая еда;
- животные;
- игрушки;
- темы;
- важные факты;
- последние истории;
- гибкая структура без необходимости каждый раз менять схему таблицы.

Логика памяти:
- ребенок говорит обычную фразу;
- extractor пытается понять, есть ли факт о ребенке;
- память обновляется автоматически;
- если ребенок добавляет новое предпочтение, оно добавляется;
- если явно говорит, что больше не любит что-то, старое значение может быть снято/заменено;
- в prompt подмешивается краткий memory context, а не вся база целиком.

Ограничения:
- списки ограничиваются искусственно, чтобы память не разрасталась бесконечно;
- в prompt попадает только компактная выжимка, чтобы не тратить лишние токены.

## Системный prompt и поведение Lumi

Prompt Lumi уже сильно доработан:
- Lumi отвечает на языке ребенка;
- обычно 1-2 коротких предложения;
- если нужно утешить/объяснить - максимум 3 коротких предложения;
- сказки строго 4-5 коротких предложений с финалом;
- ответы должны быть живыми, но без длинных монологов;
- не использовать странные буквальные звуки типа "хи-хи", если TTS произносит их плохо;
- не перескакивать на другую тему;
- не начинать игру/загадку/сказку без явной просьбы;
- если запрос неоднозначный, Lumi переспрашивает.

Исправленные поведенческие баги:
- слово "игрушка" больше не запускает игру само по себе;
- "загадка в книжке" не считается просьбой загадать загадку;
- неоднозначные фразы типа "давай поиграем загадку" вызывают уточнение;
- если ребенок прерывает сказку и говорит "классно", Lumi не должна начинать новую сказку;
- истории ограничены, чтобы не обрываться на полуслове;
- ответы на неправильные загадки теперь разные, не только "почти, но нет".

## Короткий кэшированный контент

Реализован кэш короткого контента:
- загадки;
- скороговорки;
- мини-игры;
- реакции;
- уточняющие фразы;
- ответы на правильные/неправильные загадки.

Как работает:
1. ребенок просит короткий контент;
2. сервер ищет `content_item`;
3. если аудио уже есть, берет готовый `.wav`;
4. если аудио нет, один раз делает TTS;
5. дальше повторно использует кэш.

Проверять можно через:
- `/api/content/stats`

Там видны:
- `by_type`
- `by_lang`
- `by_source`
- `cached_audio`

## Многоязычность

Сейчас поддерживаются:
- русский;
- румынский;
- английский.

Что уже сделано:
- стартовый RO/EN набор короткого контента;
- автоопределение языка запроса;
- WebSocket больше не принуждает короткий контент к русскому языку;
- ответы на загадки локализованы;
- TTS routing исправлен для auto-language.

Важное решение:
не переводить вручную все 35 файлов на каждый язык.

Текущая стратегия:
1. русский контент - мастер-база;
2. если ребенок просит на RO/EN, сервер берет русский мастер-элемент;
3. один раз адаптирует его через OpenAI;
4. сохраняет в PostgreSQL как `runtime_localized`;
5. затем использует уже готовый текст и аудио-кэш.

Так можно масштабировать на другие языки без ручного перевода всей базы.

## Тематические загадки и скороговорки

Добавлен путь для запросов по теме:
- "загадай загадку про мишку";
- "придумай загадку про кофе";
- "скороговорка про попугая";
- "tell me a riddle about coffee";
- "spune o ghicitoare despre iepure".

Логика:
1. классификатор понимает тип: `riddle` или `tongue_twister`;
2. извлекает тему после `про`, `о`, `об`, `about`, `despre`;
3. создает тематический короткий элемент через OpenAI;
4. сохраняет его как `runtime_themed`;
5. для загадки сохраняет варианты правильного ответа;
6. генерирует аудио один раз и дальше берет из кэша.

Если генерация не удалась, сервер падает обратно на обычный готовый кэш.

## LLM Router и переключение моделей в browser demo

Добавлен слой LLM router для быстрого сравнения моделей в браузерном демо.

Важно:
- WebSocket pipeline для ESP32 не менялся;
- STT не менялся;
- TTS не менялся;
- системный prompt Lumi не менялся;
- переключение работает через `POST /chat`.

Поддерживаемые режимы:
- `gpt` -> OpenAI `gpt-4o-mini`;
- `deepseek` -> DeepSeek `deepseek-v4-flash` через OpenAI-compatible API;
- `auto` -> быстрый rule-based router.

Auto Router сейчас работает без отдельного LLM-классификатора, чтобы не добавлять задержку.

Правила Auto Router:
- простые игровые запросы, загадки, сказки, скороговорки, факты, счет -> DeepSeek;
- эмоции, страхи, ссоры, семья, школа, опасность, память ребенка -> GPT;
- если `DEEPSEEK_API_KEY` отсутствует или DeepSeek падает -> fallback на GPT.

Browser demo отправляет:

```json
{
  "text": "...",
  "lang": "ru-RU",
  "model": "auto"
}
```

`POST /chat` возвращает:

```json
{
  "reply": "...",
  "model_used": "gpt-4o-mini",
  "provider": "openai",
  "latency_ms": 1234
}
```

Для ответов из content cache:
- `provider: "content_cache"`;
- `model_used: null`;
- `latency_ms: 0`.

## Story Engine

Истории/сказки теперь:
- короткие;
- 4-5 предложений;
- с обязательным финалом;
- используют контекст из базы: шаблоны, персонажей, места, объекты, эмоции, проблемы, награды, мир Lumi;
- не должны обрываться на полуслове из-за лимита токенов.

Лимит:
- `maxTokens` для story установлен около 230.

Если ребенок комментирует историю после прерывания, server добавляет follow-up context, чтобы Lumi не начинала новую историю без просьбы.

## Важные решения, которые не надо пересматривать заново

- PostgreSQL выбран сразу, JSON-файл не используем как основное хранилище.
- `device_id` - правильная основа для памяти устройства.
- Русский контент - мастер-база; другие языки создаются автоматически по требованию.
- Короткий повторяемый контент должен кэшироваться в аудио.
- Игры/загадки/сказки запускаются только по явной просьбе.
- При неоднозначности Lumi переспрашивает.
- Сказки должны быть короткими и завершенными.
- Ответы должны быть короче, с простыми фразами и паузами.
