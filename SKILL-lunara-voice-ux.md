# SKILL: Voice UX для Lunara Toy

**Когда применять:** всегда при работе над голосовым взаимодействием Lunara — голос,
задержка, поведение при коротком/нераспознанном вводе, мультиязычность EN/RO/RU, характер Lumi.
Триггеры: tts.js, llm.js, голос Lumi, «игрушка тупит / звучит роботом / разные голоса»,
push-to-talk, латентность.

> ⚠️ Эта версия написана по **реальному коду сервера** (lunara-toy-server), а не по общим
> советам из статей про голосовых агентов. Многие «универсальные» советы к этой архитектуре
> НЕ применимы — см. раздел «Чего НЕ делать».

---

## Реальная архитектура (факты, не догадки)

- **Самописный пайплайн** на WebSocket (`ws`), без фреймворков (нет Pipecat/LiveKit/Vapi).
- **Ввод — push-to-talk, hold-to-talk:** ребёнок ДЕРЖИТ кнопку и говорит. Устройство шлёт
  `start` → стримит PCM → `end`. Сервер обрабатывает только по `end`.
- **Пайплайн линейный и блокирующий:** `Whisper (STT) → GPT-4o-mini (LLM) → TTS → WAV`.
  Ничего не стримится; игрушка ждёт полного прохода всей цепочки.
- **STT:** OpenAI Whisper, автоопределение языка.
- **LLM:** `gpt-4o-mini`, max_tokens 180, история 10 сообщений, общий системный промпт
  (легенда «Звёздный Мишка») + короткая языковая инструкция.
- **TTS — роутер по языку (осознанный выбор, Вариант Б):**
  - Русский → **Yandex SpeechKit**, голос `alena`, speed 0.85 (топ-качество русского).
  - Румынский → OpenAI `tts-1`, голос `nova`.
  - Английский → OpenAI `tts-1`, голос `shimmer`.
- **Аудиоформат:** PCM 16 kHz 16-bit mono (+ WAV для браузер-демо).

## Характер Lumi

- **Lumi — он (мужской пол) по умолчанию.** НО родитель/клиент может сменить пол в настройках.
- Из-за конфигурируемого пола **системные фразы держим гендерно-нейтральными**, чтобы звучали
  верно при любой настройке (пример: «Скажи ещё разочек, пожалуйста?» — без рода).
- Если правишь характер в промпте — следи за согласованием рода ИЛИ оставляй нейтрально.
  (В текущем промпте есть разнобой: «Мишка» = он, но местами «я рада» = она — причесать.)

## Приоритеты настройки (под ЭТУ архитектуру)

### 1. Единство голоса — осознанный компромисс, НЕ баг
Сейчас Lumi звучит разными голосами в разных языках (Yandex для ru, OpenAI для ro/en).
Это **выбранный компромисс (Вариант Б):** ради топового русского жертвуем единством голоса.
- НЕ «чинить» это сведением к одному провайдеру без явного решения — русский просядет.
- Если приоритет сменится на «один друг во всех языках» -> перевести все три на OpenAI
  (один голос, но русский чуть проще). Это продуктовое решение, а не техническое.

### 2. Тёплые реакции вместо сухих ошибок (внедрено)
Короткое нажатие (`audioBytes < 1600`) или пустой транскрипт -> Lumi НЕ отдаёт `error`,
а проигрывает кешированную тёплую просьбу повторить (`retry_ru.pcm`, генерится при старте).
- Принцип: для ребёнка 3–8 «ошибка» = обида. Любой сбой ввода = живая реакция друга.
- Сейчас retry только на русском (язык неизвестен, т.к. речи не было). Будущее улучшение —
  3 языковых версии + память последнего языка ребёнка.

### 3. Латентность — главный тормоз НЕ промпт
Реальная задержка — в **последовательном блокирующем пайплайне** (полный STT -> полный LLM ->
полный TTS -> скачивание -> проигрыш). Это секунды.
- Самый большой выигрыш: **стриминг** — начинать TTS, не дожидаясь конца ответа LLM.
- Ужать системный промпт можно (~100–200 мс), но это вторично на фоне архитектуры.

## Чего НЕ делать (типичные ложные советы)

- НЕ настраивай turn detection / порог тишины на сервере — его нет и не нужно.
  Ввод по кнопке: ребёнок держит — паузы не обрывают. Конец решает кнопка, не сервер.
- НЕ «разделяй промпт по языкам» ради скорости — мультиязычная часть промпта крошечная,
  выигрыш почти нулевой. Объём промпта — это легенда персонажа, не язык.
- НЕ своди три голоса к одному без явного продуктового решения — потеряешь топ-русский.
- НЕ выдавай ребёнку сухие технические ошибки — только тёплые голосовые реакции.
- НЕ жертвуй чистотой речи ради «естественности» — игрушка ещё и языковой образец.

---

## Порядок работы при запросе на «оживить / ускорить»

1. Уточни, что именно болит: голос (единство?), скорость (стриминг?), или UX-реакции.
2. Скорость -> смотри в сторону стриминга TTS, а не промпта.
3. Голос -> это продуктовый выбор (Вариант А единый / Б топ-русский), а не правка кода вслепую.
4. Сухие ошибки -> заворачивай в голосовую реакцию Lumi (паттерн retry уже есть в server.js).
