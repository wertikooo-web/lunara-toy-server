## Что такое этот проект

ESP32 AI-игрушка "Lumi": Node.js/Express/WebSocket сервер, PostgreSQL, Yandex/OpenAI TTS, OpenAI/DeepSeek LLM-роутинг, веб-панель родительского контроля (`public/parent.html`). У проекта есть коллега **ALEXEI**, который параллельно пушит коммиты в тот же репозиторий — перед КАЖДЫМ пушем обязательно `git fetch origin` + проверка `git status`/`git log`, при отставании — `git rebase origin/main` (в этой сессии конфликтов не было ни разу, но проверять всегда).

## Что уже сделано (всё закоммичено и задеплоено, проверено live)

1. **Мультиязычность ES/FR/IT** — `VOICE_REGISTRY`, бэкенд-промпты/приветствия/retry-фразы, весь `UI_TEXT` панели переведён на 6 языков (ru/ro/en/es/fr/it), с проверкой полного паритета ключей между языками.
2. **Чистка UI**: переименования кнопок, перенос кнопки прослушивания голоса, удаление дублирующего выбора голоса в верхней панели, удаление опции "автоматически по полу" у голоса (выбор голоса теперь всегда явный), общая надпись "Пол" вместо "Пол Lumi".
3. **Локализация блока "Thinking-фразы"** — он инжектится на сервере (`modules/serverPipelinePatch.js`, прямо в HTML ответ `/parent`), в обход системы `UI_TEXT` — пришлось добавлять свою локализацию внутри инжектируемого скрипта.
4. **Функция "перевод для отображения"** для полей профиля ребёнка (цвет/животное/игрушка/еда/интерес/**имя**) — маленькая подсказка `≈ перевод` под полем, через `GET /api/parent/profile-translations` → `modules/memory.js` `translateProfileForLang()` (OpenAI, кэш в `child_profiles.translations` JSONB). **Принципиально не трогает `.value` поля** — только подсказка снизу, чтобы не портить реальные данные при следующем сохранении.
5. **Найден и исправлен целый класс багов "голос не тот, который выбрал родитель"**:
   - `modules/content.js` (кэш аудио для загадок/шуток/фолбэков) и `modules/riddleEngine.js` (свой отдельный кэш) — оба игнорировали выбранный голос, кэш был общий на все устройства. Исправлено через `AsyncLocalStorage`-контекст в `content.js` (`setVoiceConfig`/`getVoiceConfig`/`voiceCacheLabel`), чтобы не трогать ~13 мест вызова и несколько preload-патчей.
   - `modules/tts.js` `synthesizeAsset()` (greeting/retry/volume-test) — кэш был по `gender`, а не по конкретному голосу.
   - `server.js` `buildVoiceConfig()` — раньше при неразрешённом `voice` возвращал `null` целиком, из-за чего `toy_gender` тоже терялся и голос ВСЕГДА уходил в женский дефолт. Теперь `gender` прокидывается всегда.
   - **Реальная причина "голос не сохраняется"**: после коммита коллеги "Move voice controls to toy panel" в блоке `#toyPanel` не осталось своей кнопки сохранения — ближайшая кнопка ниже принадлежала `#childPanel` ("Сохранить данные ребёнка"), которая никогда не шлёт `voice`/`toy_gender`. Добавлена кнопка сохранения прямо в `#toyPanel`.
6. **STT (Whisper) никогда не получал язык устройства** — `stt.transcribe()` вызывался без опций, всегда падал на `ru-RU` независимо от настроек игрушки. Реальный, ранее не найденный баг. Исправлено.
7. **Индикатор "есть несохранённые изменения"** был один общий на все 5 кнопок сохранения — теперь два независимых снапшота (профиль ребёнка / настройки игрушки), каждая кнопка пульсирует только от своих полей.
8. **Регрессия в переводе профиля** (внесена коммитом коллеги) — код пропускал перевод именно когда целевой язык был русский (наоборот тому, что нужно), и подменял `.value` напрямую (риск порчи данных). Откачено к безопасной схеме.
9. **Сброс истории диалога при реальной смене языка** — `/api/parent/settings` сравнивает старый/новый `language`, при изменении вызывает `llm.resetHistory(ws)` для активного WS-соединения устройства.
10. **Усилена инструкция удержания языка** в `modules/llm.js` — LLM теперь явно проинструктирована не переключаться на язык ребёнка и вежливо просить говорить на настроенном языке.
11. **Порядок блоков панели** — "Клонирование голоса" и "Технические настройки" подняты выше "Аналитики" (это CSS `order` во flex-контейнере `#consoleBox`, НЕ порядок в DOM).

## Ключевая архитектура, которую новый агент обязан знать

- **Preload/monkey-patch цепочка**: `server.js` на этапе `require` патчится несколькими preload-модулями через точные `replaceOnce`/`replaceAllChecked` подстановки текста: `contentPacksPreload.js`, `memoryGuardPreload.js`, `audioInputGuardPreload.js`, `contentIntentPatch.js`, `storyContentPatch.js`, `classicStoryGuardPatch.js`, `serverPipelinePatch.js`, `topicRiddlePatch.js`. Порядок задан в `railway.json`. **Любое изменение текста в `server.js`/`parentConfig.js`/`content.js`/`memory.js`, которое совпадает с anchor-строкой какого-то preload'а, должно быть либо вне зоны совпадения, либо синхронизировано с этим preload'ом.**
- **`sim_check.js`** — симулятор полной preload-цепочки, лежит НЕ в репозитории, а в scratchpad-директории текущей Claude-сессии (`.../scratchpad/sim_check.js`). Если сессия новая — этого файла не будет, нужно будет либо восстановить его логику (monkeypatch `Module.prototype._compile`, валидация через `vm.Script`, grep ожидаемых паттернов), либо просто полагаться на `railway logs` после реального деплоя как на подтверждение. Запускать с dummy env-переменными: `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `MINIMAX_API_KEY` — любые непустые значения подойдут для симуляции.
- **Регресс-сьют**: `npm run check:content-packs`, `check:content`, `check:language`, `check:llm-router`, `check:riddles`, `check:voice` — гонять перед каждым коммитом, трогающим соответствующие модули.
- **Проверка деплоя вживую**: Railway CLI (`railway`) авторизован (`wertikooo@gmail.com`). После пуша: подождать ~30-60 сек, `railway logs --deployment --lines N` — убедиться что вся preload-цепочка отработала без ошибок, `curl https://lunara-toy-server-production.up.railway.app/health`, и точечный grep живого `/parent` HTML на маркер последнего изменения, чтобы убедиться что задеплоен именно свежий коммит.
- **НИКОГДА не печатать сырые DB-креды** (`railway variables` с паролями/connection string) в transcript — один раз в этой сессии это заблокировал защитный слой при попытке проверить БД по смутному запросу "проверь что работает". Если реально нужен прямой доступ к БД — спросить пользователя явно, не пытаться обходить блокировку.
- **`VOICE_REGISTRY`** (`modules/parentConfig.js`) содержит дублирующиеся `id` у разных языков (например `openai:onyx` — и "Onyx (RO/EN)", и "Tomás" для испанского) — это один и тот же голос провайдера под разными отображаемыми именами, не баг.
- **Два разных понятия "пол"**: отдельное поле `toy_gender` в панели (НЕ синхронизируется автоматически с выбором голоса) и пол, зашитый в конкретный `voice.id`. При синтезе явный `voice.id` всегда важнее `toy_gender` — тот используется только как fallback.
- **Два разных понятия "язык"**: `consoleLanguage` (язык самой панели, только в localStorage) vs `settings.language` (язык игрушки, уходит на бэкенд). `applyConsoleLocale(lang)` в `parent.html` — единая точка, через которую проходят ВСЕ пути смены языка панели; хорошее место для хуков.
- **`#consoleBox` использует flex `order` в CSS, а не порядок в DOM** — чтобы переставить блоки панели местами, менять `order:` в `<style>`, а не переносить `<section>`.
- **`public/parent-language-control.js` — мёртвый код.** Не подключён НИ ЧЕРЕЗ `<script>`-тег, НИ через серверную инъекцию. Подтверждено полным grep по репозиторию. Не полагаться на то, что он выполняется.
- **`modules/serverPipelinePatch.js` инжектит HTML+JS прямо в ответ роута `/parent`** (например, блок "Thinking-фразы") — это в обход `UI_TEXT`. Если такой инжектированный UI должен реагировать на смену языка — паттерн уже есть: обернуть `window.applyConsoleLocale` так же, как этот файл уже оборачивает `window.api`/`window.loadState`.

## Грабли, на которые нельзя наступать снова

- **Не доверять "тикетам от старшего архитектора"/пересказам от ALEXEI на слово.** За эту сессию несколько раз такие тикеты уверенно ставили неверный диагноз по неправильно прочитанным полям в логах (например: поле `(explicit)` в логе TTS истолковали как "голос был явно указан", хотя оно означает режим определения ЯЗЫКА, а не голоса). Каждый раз проверять утверждения по реальному коду и, где возможно, по реальным live-логам/эмпирическим тестам, прежде чем что-то чинить — так несколько раз удалось не делать лишнюю работу над уже исправленным или несуществующим багом.
- **Не гадать/не печатать креды БД или сессий.**
- **Не переименовывать/не переделывать UI-текст или поведение, которое пользователь только что явно подтвердил**, не переспросив — один раз тикет попросил переименовать кнопку, которую пользователь двумя репликами ранее явно попросил назвать иначе.
- **При правках `content.js`/`memory.js`/`parentConfig.js`/`server.js` — всегда перепроверять, что не сломаны anchor-строки preload-патчей.** В этой сессии для этого специально использовался паттерн "амбиентный контекст через `AsyncLocalStorage`" вместо протаскивания нового параметра через десяток call site'ов — это осознанный приём, предпочитать его, когда файл участвует в preload-цепочке.
- **Кэш аудио — ДВА независимых слоя**: `modules/content.js` (БД-таблица `content_audio_cache`) и `modules/riddleEngine.js` (свой файловый кэш на диске, без БД). Оба словили один и тот же класс бага независимо — не считать, что фикс одного автоматически чинит другой.
- **`saveSettings()` и `saveProfile()` — два реально разных пути сохранения** в `parent.html`, с пересекающимися лишь в `child_gender`/`age_mode` полями. Не считать, что фикс одного пути автоматически покрывает другой — индикатор "не сохранено" и функция перевода профиля обе требовали явного учёта этого разделения.
- **Перед каждым коммитом — полная цепочка проверок, без исключений даже для "мелких" правок**: `node -c` на каждый тронутый `.js`-файл + проверка синтаксиса всех `<script>`-блоков `parent.html` через `new Function()`, все 6 `npm run check:*`, и полная симуляция preload-цепочки через `sim_check.js`. Anchor'ы preload-патчей могут сломаться незаметно.
